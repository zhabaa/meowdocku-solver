# Бот для Meowdoku

Скриншот с телефона -> определить, что на экране -> разобрать поле ->
единственная расстановка кошек -> тапы. И так по кругу, уровень за уровнем.

## Правила игры

Поле N×N цветных клеток, кошек ровно N. Требования:

- одна кошка на цвет,
- одна кошка на строку,
- одна кошка на столбец,
- кошки не касаются: ни своих, ни чужих, даже по диагонали, то есть все
  8 соседей клетки свободны.

Управление: одиночный тап ставит крестик, двойной — котика. Крестики не нужны,
поэтому бот делает только двойные тапы. При неверном двойном тапе игра
отнимает жизнь.

## Запуск

```
.venv/bin/python main.py                # крутить уровни с телефоном
.venv/bin/python main.py --levels 5     # остановиться после пяти уровней
.venv/bin/python main.py --dry-run      # показать решение, телефон не трогать
.venv/bin/python main.py --image путь   # разобрать сохранённый скриншот
```

Телефон подключается по USB, отладка включается в настройках разработчика.

## Устройство

| Файл | Что делает |
|---|---|
| `field.py` | читает поле со скриншота: размер, цвета, найденные котики, координаты тапа |
| `screens.py` | определяет, что на экране: поле, уровень пройден, лидеры или непонятно |
| `solver.py` | находит единственную расстановку кошек |
| `emulate.py` | скриншоты и тапы через adb |
| `annotate.py` | рисует разбор поверх скриншота |
| `main.py` | цикл прохождения уровней |
| `fake_phone.py` | подделка телефона для тестов |

## Цикл

```
снять экран -> определить тип
  поле        -> решить единственным способом и поставить кошек,
  пройден     -> одиночный тап в оранжевую кнопку,
  лидеры      -> одиночный тап в жёлтую надпись,
  неизвестно  -> остановиться.
```

Переходы: тап, дальше снимок раз в секунду. Пока тип экрана не сменился, тап
повторяется в ту же точку. С котиками то же самое: двойной тап, ждём появления
котика в нужной клетке, не появился — повторяем в ту же точку.

Ограничители: `--levels` и `--steps`, чтобы цикл не крутился вечно.

## Тесты

```
.venv/bin/python test_field.py
.venv/bin/python test_solver.py
.venv/bin/python test_screens.py
.venv/bin/python test_emulate.py
.venv/bin/python test_loop.py
```

Без pytest, каждый файл запускается отдельно и печатает, что пройдено.

`test_loop.py` гоняет цикл на подделке телефона: берём настоящий скрин
пустого поля, а на двойной тап подставляем спрайт котика, вырезанный из того
же поля с уже стоящим котом. Расхождение с настоящим скрином 0.5% пикселей по
краям спрайта, то есть поле читается ровно так же.

## Почему так сделано

**Без гадания.** Расстановка всегда единственная, и она проверяется до первого
тапа. Попасть в пустую клетку невозможно, поэтому жизни не тратятся. Если решений
оказалось больше одного или нет — поле прочиталось неверно: бот сохраняет
скриншот в `img/tmp/failed.png` и останавливается.

**Повторять тап в ту же клетку безопасно.** Жизнь тратится только за попадание в
пустую клетку, а повтор бьёт точно в ту же.

**Клетки ищем по насыщенности, а не по порогу яркости.** Первая версия брала
`threshold(220)` и находила контурами 12 строк и 2 столбца вместо 8×8: мимо
проходили иконки котиков вверху и кнопки внизу. Сейчас клетки — связные
компоненты по маске `S > 40 & V > 60`, отфильтрованные по пропорциям сторон.
Размер определяется сам, хардкод пикселей не нужен.

**Цвет клетки берём модой по кольцу.** Кольцо — полоска шириной 10% от края,
внутренняя часть исключена: там рисуется котик. Медиана не годится — белый
бордюр и скруглённые углы занимают заметную долю и утягивают её в фон
(клетка отдавала `[215,191,167]` вместо своего цвета).

**Тап в центр клетки.** Раньше было смещение (−2.6%, −5.1%), но перемер на семи
котиках с четырёх скринов показал: кот рисуется по центру, отклонение меньше
пикселя. Прежнее смещение измерялось по маске, захватившей бордюр клетки.

**Точки тапов ищем по картинке, а не задаём числами.** Кнопка бывает и
«Золотая рыбка», и «Уровень 334», но выглядит одинаково.

**Смену экрана определяем по типу, а не по разнице картинок.** Два разных
экрана лидеров отличаются на 16 единиц, а одно поле до и после установки трёх
кошек — на 0.7. Порог по пикселям дал бы ложное «экран сменился» и зависание.

**Двойной тап — одной командой adb.** Два отдельных вызова `input tap` дают
между тапами сотни миллисекунд на запуск adb, и игра такой тап двойным не
считает. Оба нажатия уходят одним `input motionevent`.

**Самопроверки при чтении.** Перед тапом проверяем, что клеток ровно N²,
строк и столбцов поровну, цветов ровно N и каждый цвет образует связную
область. Разрыв внутри цвета означает, что два цвета слились — это главный
признак плохого чтения.

## Замеры

| Поле | Решений | Время |
|---|---|---|
| 8×8 | 1 | 0.001 с |
| 9×9 | 1 | 0.004 с |
| 10×10 | 1 | 0.026 с |

Солвер сверялся с полным перебором перестановок на полях из `img/tmp` и на 400
случайных досок.

Правило «кошки не касаются» — это именно 8 соседей. Проверено на трёх полях:
при 8 соседях решение единственное, при 4 соседях решений несколько.
