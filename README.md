# Бот для Meowdoku

Скриншот с телефона -> определить, что на экране -> прочитать поле ->
единственная расстановка кошек -> тапы. И так по кругу, уровень за уровнем.

## Правила игры

Поле N×N цветных клеток, кошек ровно N. Требования:

- одна кошка на цвет,
- одна кошка на строку,
- одна кошка на столбец,
- кошки не касаются: ни своих, ни чужих, даже по диагонали, то есть все
  8 соседей клетки свободны.

Управление: одиночный тап ставит крестик, двойной — котика. Крестики не
нужны, поэтому бот делает только двойные тапы. При неверном двойном тапе
игра отнимает жизнь.

## Запуск

```
.venv/bin/python main.py                # один уровень
.venv/bin/python main.py --levels 5     # пять уровней
.venv/bin/python main.py --levels 0     # без ограничения
.venv/bin/python main.py --dry-run      # показать решение, не тапать
.venv/bin/python main.py --image путь   # разобрать сохранённый скриншот
.venv/bin/python main.py --verbose      # подробный лог в консоль
.venv/bin/python main.py --log путь     # куда писать лог
```

Телефон подключается по USB, отладка включается в настройках разработчика.
Лог всегда пишется в `img/tmp/bot.log`, флаг `--verbose` включает ещё и
консоль.

Пороги можно переопределить из окружения, не правя код:

```
MEOWDOKU_CAT_DARK_RATIO=0.2 .venv/bin/python main.py
```

## Структура

```
main.py           разбор аргументов, сборка зависимостей, запуск
take_screenshot.py  снять скриншот с телефона в img/tmp

meowdoku_bot/
  config.py       все 43 порога с объяснением, откуда значение
  logging_setup.py  логгер
  domain.py       Cell, CellBox, ScreenKind
  field.py        чтение поля: CellDetector, ColorReader, CatDetector, BoardReader
  screens.py      определение экрана: ScreenClassifier и наследники Screen
  solver.py       Solver — поиск единственной расстановки
  device.py       AdbDevice — скриншоты и тапы через adb
  annotate.py     Annotator — разбор поверх скриншота
  game.py         игровой цикл: BoardValidator, LevelPlayer, GameBot

fake_phone.py     подделка телефона для тестов цикла
test_*.py         тесты, каждый запускается сам по себе
```

Зависимости идут в одну сторону, циклов нет:

```
domain  ←  config  ←  logging_setup
   ↑         ↑
field ← screens
   ↑    ↑      ↑
solver  device  annotate
   ↑         ↑
   └──── game.py ────┘
                ↑
              main.py
```

Все зависимости передаются в конструкторы: `GameBot(device, classifier,
player, validator, annotator, settings, work_dir)`. Поэтому в тестах
подменяется один объект подделки, а не десяток глобальных переменных.

## Игровой цикл

```
снять экран -> определить тип
  поле        -> решить единственным способом и поставить кошек,
  пройден     -> одиночный тап в оранжевую кнопку,
  лидеры      -> одиночный тап в жёлтую надпись,
  неизвестно  -> переснять и попробовать снова.
```

Переходы: тап, дальше снимок раз в секунду. Пока тип экрана не сменился, тап
повторяется в ту же точку. С котиками то же самое: двойной тап, ждём
появления котика в нужной клетке, не появился — повторяем в ту же точку.

## Почему так сделано

**Без гадания.** Расстановка всегда единственная, и она проверяется до
первого тапа. Попасть в пустую клетку невозможно, поэтому жизни не тратятся.
Если решений несколько или нет — поле прочиталось неверно, и бот
переснимает экран вместо тапа.

**Повторять тап в ту же клетку безопасно.** Жизнь тратится только за
попадание в пустую клетку, а повтор бьёт точно в ту же.

**Клетки ищем по насыщенности, а не по порогу яркости.** Первая версия брала
`threshold(220)` и находила контурами 12 строк и 2 столбца вместо 8×8: мимо
проходили иконки котиков вверху и кнопки внизу. Сейчас клетки — связные
компоненты по маске `S > 40 & V > 60`, отфильтрованные по пропорциям сторон.
Размер определяется сам, хардкод пикселей не нужен.

**Цвет клетки берём модой по кольцу.** Кольцо — полоска шириной 10% от края,
внутренняя часть исключена: там рисуется котик. Медиана не годится — белый
бордюр и скруглённые углы занимают заметную долю и утягивают её в фон.

**Крестик не путаем с котиком.** У обоих больше половины пикселей отличаются
от цвета клетки. Различает тёмная морда: у котиков 44–52% пикселей темнее
140, у крестика ноль.

**Котик с серой мордой не ломает сетку.** Его клетка почти не попадает в
маску насыщенности. Тогда сетка достраивается по найденным соседям, если
шаги между ними ровные.

**Тап в центр клетки.** Раньше было смещение (−2.6%, −5.1%), но перемер на
семи котиках с четырёх скринов показал: кот рисуется по центру, отклонение
меньше пикселя. Прежнее смещение измерялось по маске, захватившей бордюр.

**Точки тапов ищем по картинке, а не задаём числами.** Кнопка бывает и
«Золотая рыбка», и «Уровень 334», но выглядит одинаково. А жёлтые клетки
поля после морфологии тоже дают широкий блок — отсекаем по заливке и
пропорциям.

**Смену экрана определяем по типу, а не по разнице картинок.** Два разных
экрана лидеров отличаются на 16 единиц, а одно поле до и после установки трёх
кошек — на 0.7. Порог по пикселям дал бы ложное «экран сменился».

**Двойной тап — одной командой adb.** Два отдельных вызова `input tap` дают
между тапами сотни миллисекунд на запуск adb, и игра такой тап двойным не
считает.

## Пороги

Все значения живут в `meowdoku_bot/config.py` с комментарием, откуда каждое. Самые
неочевидные:

| Порог | Значение | Почему |
|---|---|---|
| `board.size_tolerance` | 0.15 | внутри поля клетки отличаются на пиксель, посторонние квадратики — на десятки. При 0.3 проходил лишний квадрат 70×70 рядом с клетками 94×95 |
| `cat.dark_ratio` | 0.15 | у котиков 44–52% тёмных пикселей, у крестика 0. Запас трёхкратный |
| `screen.button_min_fill` | 0.75 | настоящая кнопка залита на 95%, слипшиеся жёлтые клетки — на 45% |
| `screen.button_min_aspect` | 2.0 | кнопка шире высоты в 4.7 раза, слипшиеся клетки вдвое выше ширины |
| `timing.min_board_size` | 4 | на переходах ловились кадры, читающиеся как поле 1×1 |

## Тесты

```
.venv/bin/python test_logging.py
.venv/bin/python test_config.py
.venv/bin/python test_field.py
.venv/bin/python test_solver.py
.venv/bin/python test_screens.py
.venv/bin/python test_device.py
.venv/bin/python test_loop.py
```

Без pytest, каждый файл запускается отдельно и печатает, что пройдено.

`test_loop.py` гоняет цикл на подделке телефона: берём настоящий скрин
пустого поля, а на двойной тап подставляем спрайт котика, вырезанный из
того же поля с уже стоящим котом. Расхождение с настоящим скрином 0.5%
пикселей по краям спрайта, то есть поле читается ровно так же.

## Замеры

| Поле | Решений | Время |
|---|---|---|
| 8×8 | 1 | 0.001 с |
| 9×9 | 1 | 0.004 с |
| 10×10 | 1 | 0.026 с |

Солвер сверялся с полным перебором перестановок на полях из `img/tmp`,
`img/screenshots` и на 400 случайных досок.

Правило «кошки не касаются» — это именно 8 соседей. Проверено на трёх полях:
при 8 соседях решение единственное, при 4 соседях решений несколько.
