# Бот для Meowdoku

Скриншот с телефона -> разбор поля -> единственная расстановка кошек -> двойные тапы.

## Правила игры

Поле N×N цветных клеток, кошек ровно N. Требования:

- одна кошка на цвет,
- одна кошка на строку,
- одна кошка на столбец,
- кошки не касаются, даже по диагонали.

Управление: одиночный тап ставит крестик, двойной — котика. Крестики не нужны,
поэтому бот делает только двойные тапы. При неверном двойном тапе игра
отнимает жизнь, их всего три.

## Запуск

```
.venv/bin/python main.py                # с телефоном
.venv/bin/python main.py --dry-run      # показать решение, телефон не трогать
.venv/bin/python main.py --image путь   # разобрать сохранённый скриншот
```

Телефон подключается по USB, отладка включается в настройках разработчика.

## Устройство

| Файл | Что делает |
|---|---|
| `field.py` | читает поле со скриншота: размер, цвета, найденные котики, координаты тапа |
| `solver.py` | находит единственную расстановку кошек |
| `emulate.py` | скриншоты и двойные тапы через adb |
| `annotate.py` | рисует разбор поверх скриншота |
| `main.py` | цикл прохождения одного поля |

Тесты: `test_field.py`, `test_solver.py`, `test_emulate.py`, `test_main.py`.
Запускаются по одному, без pytest:

```
.venv/bin/python test_field.py
```

## Почему так сделано

**Без гадания.** В игре три жизни, и расстановка всегда единственная, так что
решаем полностью до первого тапа. Если решений оказалось больше одного или
вовсе нет — это значит, что поле прочиталось неверно. Тогда бот останавливается
и сохраняет скриншот в `img/tmp/failed.png`, а не тапает наугад.

**Клетки ищем по насыщенности, а не по порогу яркости.** Первая версия брала
`threshold(220)` и находила контурами 12 строк и 2 столбца вместо 8×8: мимо
проходили иконки котиков вверху и кнопки внизу. Сейчас клетки — это связные
компоненты по маске `S > 40 & V > 60`, отфильтрованные по пропорциям сторон.
Размер определяется сам, хардкод пикселей не нужен.

**Цвет клетки берём модой по кольцу.** Кольцо — полоска шириной 10% от края,
внутренняя часть исключена: там рисуется котик. Медиана не годится — белый
бордюр и скруглённые углы занимают заметную долю и утягивают её в фон
(клетка отдавала `[215,191,167]` вместо своего цвета).

**Тап смещён от центра клетки** на (−2.6% по X, −5.1% по Y): котик рисуется
чуть выше и левее. Смещение задано долями от размера клетки, поэтому работает
при любом масштабе экрана.

**Двойной тап — одной командой adb.** Два отдельных вызова `input tap` дают
между тапами сотни миллисекунд на запуск adb, и игра такой тап двойным не
считает. Оба нажатия уходят одним `input motionevent`.

**Самопроверки при чтении.** Перед тапом проверяем, что клеток ровно N²,
строк и столбцов поровну, цветов ровно N и каждый цвет образует связную
область. Разрыв внутри цвета означает, что два цвета слились — это главный
признак плохого чтения.

## Замеры

| Поле | Решений | Время |
|---|---|---|
| 8×8 | 1 | 0.001 с |
| 9×9 | 1 | 0.004 с |
| 10×10 | 1 | 0.026 с |

Солвер сверялся с полным перебором перестановок на четырёх реальных полях и на
400 случайных досок.
